# 阶段 E：回填与复盘

依据：`brand/sop.md` 第 5、6 节（限流判定、复盘指标）。
改动范围：各天的 `log.md`（只追加和填空）、`brand/formats.md` 的「成绩」表、`weekly/<YYYY-Www>.md`。
**不改任何 `plan.md` 的 `## 预测`**。`sop.md`、`formats.md` 的规则部分、`rubric.md` 只在周复盘、用户批准后才改。

## 1. 找到期的帖子

读最近 7 天的 `daily/*/log.md`。发布时间已过 24 小时、「24h 播放」还空着的，或已过 72 小时、「72h 播放」还空着的，就是到期的帖子。没有到期的就跳过第 2–3 步。

## 2. 抓数据

用 Roxy **发布窗口**（`brand/accounts.md`），只打开自己帖子的数据页，不搜索、不刷 For You：

| 平台 | 去哪看 |
|---|---|
| TikTok | TikTok Studio → Posts → 该帖 → Analytics：播放、平均观看时长、完播率、流量来源（For You 占比）、观众地区（美国占比）、点赞评论分享、主页访问 |
| X | 帖子下方的 analytics 图标：曝光、互动、链接点击 |
| Instagram | Reel → View insights |
| YouTube | Studio → Content → 该 Short → Analytics |

填进 `log.md` 对应列。拿不到的数据写 `?`，并在对话里请用户报数，不要估。
「意向评论」列要读评论自己数：问"用什么做的 / 多少钱 / 怎么做"的，加上来要活动福利的，每人算一条。

## 3. 复盘

在当天 `log.md` 末尾的 `## 复盘` 下，每个到期帖子追加一段（已有的不改）：

```markdown
### <平台> T+1 / T+3
- 预测：<抄 plan.md ## 预测>　实际：<数据>　命中：是 / 偏高 / 偏低
- 限流判定：正常 / 疑似限流（命中 sop.md 第 5 节第 N 条）→ 处理：…
- 原因（一句）：钩子 / 选题 / 时长 / 发布时间 / 平台因素，要有数据支撑，比如"平均观看 4.1s，前 3 秒留存只有 38%，问题在钩子"
- 下次怎么做（一句）
```

疑似限流时按 `sop.md` 第 5 节处理，并在对话里告诉用户。需要用户动手的（停发、换号检查）先问再做。
然后把 TikTok 24h / 72h / 完播率 / 意向评论填进 `brand/formats.md` 对应格式卡的「成绩」表。

最后看一眼这些帖子的新评论：有提问、负面或潜在用户的，按 `mkt-publish` 第 5 节草拟回复写进 `log.md` 的「评论」小节，在对话里请用户确认。

## 3.1 活动（`campaigns/` 里有「进行中」的活动时）

按 `brand/sop.md` 第 7 节：
1. 打开活动帖，按评论时间顺序把新来要码的人填进活动文件（一人一行，还没发的码先空着），码发完就停。
2. 每人起草一条公开回复和一条私信，私信里填上该行的码和带活动 UTM 的链接。在对话里列给用户确认，确认后用发布窗口逐条发出；私信发不出去，就改发"请私信我们"的公开回复。码不出现在公开回复、截图或日志以外的任何地方。
3. 10 张发完：在置顶评论下发"已发完"的回复，状态改成「已发完 <日期>」。
4. 活动第 3 天、第 7 天：请用户看后台兑换码列表（或用户授权后由你在后台查看），填「已兑换」「后续充值」；去对方主页看有没有发作品、有没有 @ 我们，有就填链接。
5. 第 7 天写活动文件的「复盘」，结论带进当周周报。

## 4. 周复盘（周一，或用户要求时）

本周 `weekly/<YYYY-Www>.md` 不存在、今天是周一（或用户说"周复盘"）时做。写：

```markdown
# 周复盘 <YYYY-Www>（<起>–<止>）

## 数据
| 日期 | 格式卡 | 选题 | 平台 | 24h | 72h | 完播率 | 预测命中 | 限流 |

## 结论
- 最好的一条和原因，最差的一条和原因（引用各天的复盘）
- 格式卡对比：各卡的条数和 24h 中位数
- 预测命中率：x / n，系统性偏高还是偏低

## 提议的修改（用户批准后执行）
| # | 文件 | 改动（新增 / 修改 / 删除） | 依据 |

## 下周测试计划
```

提议修改的规矩：
- 每条改动都要有本周数据支撑；样本少于 3 条的结论只记在 `rubric.md` 的「观察」里，不改规则。
- 改 `rubric.md` 的打分维度或权重前，先用新打法给本周及以前的帖子重新打分；新排序比旧排序更接近实际 24h 播放的排序才提议。
- 被推翻的条目、已经写成正式规则的观察，直接删掉。`[假设]` 被验证了就去掉标记。

写完在对话里列出提议的修改，等用户逐条批准，再改 `brand/sop.md`、`brand/formats.md`、`brand/rubric.md`，同时在 `sop.md` 顶部更新版本号和日期。接着按 `mkt-research` 第 2 节的深度调研补满 `candidates.md`。
